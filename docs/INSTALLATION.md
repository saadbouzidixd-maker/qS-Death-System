# Installation guide

## Requirements

- Leaf 1.21.11 or Paper 1.21.11
- Java 21 or newer
- No other plugins required
- No resource pack

## Install

1. Stop the server.
2. Copy `qSDeathSystem-1.0.0.jar` into `plugins/`.
3. Start the server. The plugin creates:
   - `plugins/qSDeathSystem/config.yml`
   - `plugins/qSDeathSystem/keys.yml` (police-tool secret — keep private, include in backups)
   - `plugins/qSDeathSystem/database.db` (+ `-wal`, `-shm`)
   - `plugins/qSDeathSystem/journal/` (normally empty)
4. Check the console: the plugin logs the SQLite path and a warning if no hospital is configured.

## Configure the hospital

1. Stand exactly where deceased players should appear (the operating room).
2. Run `/hospital set`.
3. Verify with `/hospital info` (status must be `valid`).
4. Use `/hospital teleport` for testing. This is administrative only; ordinary players have no hospital command.

If no valid hospital exists, deaths still create evidence and the player respawns at the configured fallback (`hospital.fallback: world-spawn` by default). The console logs a clear warning.

## Give the police tool

```
/qsds tool give <player>
```

Grant the permission `qscrimescenes.police` (default: op) through LuckPerms or another Bukkit permission plugin. Grant `qscrimescenes.police.give` only to staff who may hand out tools.

The tool is a wooden shovel marked in its `PersistentDataContainer` with a token stored in `keys.yml`. Renaming or re-loring it does not break identification, and an ordinary wooden shovel can never be used as one. If `keys.yml` is deleted, previously issued tools stop working; run `/qsds tool give` again.

## Permissions

See [PERMISSIONS.md](PERMISSIONS.md). Recommended LuckPerms setup:

```
/lp group police permission set qscrimescenes.police true
/lp group admin permission set qsds.admin true
```

## Configuration

`config.yml` is documented inline. Important sections:

| Section | Purpose |
| --- | --- |
| `storage` | SQLite file, busy timeout, journal folder |
| `death` | XP capture, vanilla drop suppression, placement retries |
| `evidence` | Chest locking, head and nameplate appearance |
| `police` | Tool name/lore, unbreakable/glow, report lines |
| `hospital` | Enabled flag, fallback mode/world, warning |
| `recovery` | Re-grant experience on archive recovery |
| `time` | Report date/time format and time zone |
| `messages` | All player-facing text and the report template |

`/qsds reload` reloads configuration and messages. Storage settings take effect after a restart; the database file is not moved while the plugin is running. The police tool token is not regenerated by reload.

## Database and backups

- All evidence, archives and the hospital location live in `database.db`.
- Back up `database.db`, `keys.yml` and `journal/` together while the server is stopped.
- Do not edit the database while the server is running.
- WAL mode means recent writes may be in `database.db-wal`; copy both files (or stop the server first).

## Evidence capacity

A chest has 27 slots. If a merged inventory needs more, the chest holds the first 27 stacks and the rest is stored as `overflow_items` in SQLite. Police processing archives both; `/qsds evidence recover` returns both. Armour and offhand are merged into the same payload so they are never duplicated or omitted.

## Upgrades

1. Stop the server.
2. Back up `plugins/qSDeathSystem/`.
3. Replace the jar.
4. Start the server. The schema is created with `CREATE TABLE IF NOT EXISTS`; no destructive migration runs.

## Removing the plugin

Stop the server, remove the jar, and keep or delete `plugins/qSDeathSystem/`. Existing evidence blocks in the world are not removed automatically; process or recover them first if you want the chests gone.

## Notes and limitations

- Folia is **not** supported (not claimed, not tested).
- The plugin does not implement transportation, vehicles, buses, trains, airports, tickets or public teleportation.
- There is no player-facing hospital teleport.
- The plugin does not modify unrelated gameplay mechanics.
